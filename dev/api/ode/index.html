TreeAMR.statevector — Function
statevector(fs::FieldSet)

A freshly allocated, zeroed state vector for fs — the u an ODE integrator advances. Use gather! to load the field set's current interior values into it.

Allocated on the field set's own backend, so a device-resident field set gets a device-resident state vector and the integrator never touches host memory (M6).

source
statevector(sets::Tuple{Vararg{FieldSet}})

A freshly allocated, zeroed state vector for several field sets over one forest: their segments concatenated in tuple order, each in exactly the layout statevector(sets[i]) has. That is what makes every single-set function apply to a segment — scatter!, gather!, statearray, block_mapreduce, mesh_mapreduce and volume_weighted_norm on stateview(u, sets, i) and sets[i] behave as on a separate vector.

The sets may mix centerings, nvars and ghost widths, but must share the forest, the backend and the element type, and each must hold this rank's blocks of the forest's current leaves.

u = statevector((hydro, Bx, By, Bz))
gather!(u, (hydro, Bx, By, Bz))

TreeAMR.map_blocks! — Function
map_blocks!(kernel!, fs::FieldSet, args...; closed=false, stored=false,
            workgroupsize=nothing)

Launch a KernelAbstractions kernel over every owned point of every block, with ndrange = (N, ..., N, nblocks). The kernel's global index is therefore (i1, ..., iD, b) with each i running over 1:N; add G[d] to reach the working array's stored indices.

With closed = true the loop runs over the closed range instead — N + c[d] per dimension, so a vertex-like dimension also covers the shared boundary plane (see closedview). That is what a quantity defined on a block's faces wants: a flux has N+1 faces per dimension, not N, and the extra one is the block's own high face. In a cell-centered field set the two are the same loop.

With stored = true the loop runs over every stored point of every block, ghosts included — ndrange = (size(fs.work)[1:D]..., nblocks(fs)), that is N + 2G[d] + c[d] per dimension.

The three forms index differently

Under stored = true the kernel's global index is the stored index: there is nothing to add. Under the default and under closed = true it is an offset into the owned range and the kernel adds G[d]. A kernel written for one form is wrong under the other — silently so, since both are in bounds — so a kernel meant for the stored form should not add G anywhere.

stored = true together with closed = true is an error: the closed range is a sub-range of the stored one, so asking for both is a contradiction.

The stored form exists because a pointwise pass sometimes has to cover the ghosts too. The case that asked for it is a hydrodynamics code exchanging conserved variables and recovering primitive ones from them: its reconstruction reads primitives two cells into the neighbours, so the recovery has to have run in the ghost cells as well. Which points a block stores is the mesh's business, not the application's, so the launch says stored = true rather than the application spelling out N + 2G + c for itself (see CODE.md, "Application interface").

Blocks are uniform work units, so this is one flat parallel loop. On the CPU it runs by owner (see launch_by_owner!): every block on the same thread as in every other per-block pass of the package, which is worth up to 2.4x on a many-core node, and one workgroup per block — so a kernel handed to map_blocks! must not depend on the workgroup size. The same launch runs on a device; every work item writes its own output cell, so the result does not depend on how the loop was split.

workgroupsize is handed to the KernelAbstractions launch on a device, where a kernel heavy in registers may want smaller workgroups than the backend picks; nothing leaves the choice to the backend. The CPU ignores it, since there the workgroup is the block, which is what keeps every block on its owner's thread — so code written once for every backend may pass it unconditionally.

@kernel function rhs!(du, @Const(work), @Const(h), ::Val{D}, ::Val{G}) where {D,G}
    I = @index(Global, NTuple)
    b = I[D + 1]
    c = ntuple(d -> I[d] + G[d], Val(D))       # stored (ghosted) index
    du[ntuple(d -> I[d], Val(D))..., 1, b] = work[c..., 2, b]
end

The same pass over the stored extent, which reaches the ghosts and does not shift:

@kernel function recover!(prim, @Const(cons), ::Val{D}) where {D}
    I = @index(Global, NTuple)                 # already a stored index
    b = I[D + 1]
    c = ntuple(d -> I[d], Val(D))
    prim[c..., 1, b] = sqrt(cons[c..., 1, b])
end

TreeAMR.block_mapreduce — Function
block_mapreduce(f, op, init, fs::FieldSet; vars=1:fs.nvars)
block_mapreduce(f, op, init, fs::FieldSet, u::AbstractVector; vars=1:fs.nvars)

Reduce each block's interior cells to one value: f transforms a cell value and op folds the transformed values, starting from init. The result is a host Vector of length nblocks(fs), indexed by block, with element type taken from init. init must satisfy op(init, init) == init — a neutral element does, as Base's reduce requires of its init, and so does any init under an idempotent op such as max — because on a device the fold starts from it once per lane, not once per block.

The first form reads the working array's interiors, skipping the ghosts; the second reads a state vector, which has no ghosts to skip. vars is an integer or a contiguous range of variable indices.

This is the read-side counterpart of map_blocks!, and it is the shape every diagnostic here has. Combining the values is left to the caller, because a refinement criterion wants them per block; for one number over the whole mesh, weighted or not, use mesh_mapreduce. Each block's value is bit-identical whatever the thread count, since it is computed from that block's cells alone; a floating-point combination of them is promised to roundoff only, whichever way it is written.

The values are per local block (M7): over a distributed forest they are this rank's blocks only, so a number combined from them — the largest value of a variable, which a refinement criterion needs for its scale, or a signal speed for a time step — is this rank's number, not the mesh's, and would differ between ranks. Such a number is a mesh_mapreduce, the same on every rank:

scales = [mesh_mapreduce(abs, max, zero(eltype(fs.work)), fs; vars=v)
          for v in 1:fs.nvars]

It runs wherever the data lives: threaded host reductions over per-block views on the CPU; on a device, one workgroup per block in two launches, lanes striding over the block's cells and then one work item per block folding the lanes. It synchronizes and copies back to the host, so it belongs between steps and not inside a right-hand side.

The fold is one specification on both backends, but its association is not: the host's mapreduce may reassociate op, and the lanes of the device fold split the cells differently again. The guarantee is per-block values that are bit-identical across thread counts and, for a floating-point op, agree to roundoff across backends — identical across backends is not claimed, and is not true. A device value is reproducible from run to run, since the lane fold has a fixed order.

Callbacks on a device

f and op become kernel arguments, so everything they close over must be isbits. A captured Type is the usual trip: write oftype(x, 2) rather than closing over T and calling T(2). The same rule covers captured arrays and any mutable state.

TreeAMR.mesh_mapreduce — Function
mesh_mapreduce(f, op, init, fs::FieldSet; vars=1:fs.nvars, weight=nothing)
mesh_mapreduce(f, op, init, fs::FieldSet, u::AbstractVector;
               vars=1:fs.nvars, weight=nothing)

Reduce the whole mesh to one number: the per-block values of block_mapreduce, each multiplied by weight(key) when a weight is given, combined with op. The two forms and vars are those of block_mapreduce; init is returned for a mesh with no blocks and must be a neutral element for op.

weight is a function of a block's MortonKey, evaluated on the host and converted to the type of init before it multiplies each block's value — so init has to be a floating-point value when a weight is given. It scales a block's contribution by its geometry: a cell volume, spacing(T, forest, key)^D, is what volume_weighted_norm and total_mass pass to +, and a positive weight is equally meaningful under max or min, where max |v| / h is a CFL rate.

This is the form a conserved total, a norm, or a CFL speed wants, and the one place a reduction crosses blocks: the per-block values are combined on the host, and under MPI (M7) across ranks as well, so an application never sees a communicator. The floating-point result is promised to roundoff across thread counts, rank counts and backends, not bit for bit; see block_mapreduce for what is exact.

The peak of a variable over the mesh, and the mass of another:

peak = mesh_mapreduce(abs, max, zero(T), fs; vars=1)
mass = mesh_mapreduce(identity, +, zero(T), fs; vars=2,
                      weight=key -> spacing(T, fs.forest, key)^D)

TreeAMR.volume_weighted_norm — Function
volume_weighted_norm(fs::FieldSet, u::AbstractVector; p=2)

The p-norm of a state vector with each cell weighted by its volume, normalized by the domain volume — so the result is a resolution independent RMS (or, for p = Inf, the plain maximum).

Weighting matters on an adaptive mesh: refined regions contribute more entries per unit volume simply for being refined, so an unweighted norm silently emphasizes them. This is also the shape an adaptive integrator's internalnorm needs; through M3 only fixed-dt integrators are exercised, so it is used here for error measurement.

A mesh_mapreduce with the cell volume as the weight. The value is reproducible to roundoff across thread counts and backends; on the CPU, where the partials are combined in block order, it is exact across thread counts as well.

source
volume_weighted_norm(sets::Tuple{Vararg{FieldSet}}, u::AbstractVector; p=2)

The same norm over the state vector of several field sets (see statevector): every cell of every set weighted by its volume, normalized by the sum of the sets' domain volumes, each counted once per variable as for one set. For p = Inf it is the maximum over all segments. With one set it equals the single-set norm exactly. This is the internalnorm an adaptive integrator wants for such a vector.

A fold over points yields many results from one sweep: its callback sees a whole point — the variables, the position, the block's spacing, level and tag — and folds it into any isbits accumulator, such as bins of norms by region.

TreeAMR.mesh_fold — Function
mesh_fold(rf, op, init, fs::FieldSet; vars=1:fs.nvars, tag=nothing)
mesh_fold(rf, op, init, fs::FieldSet, u::AbstractVector; vars=1:fs.nvars, tag=nothing)

Fold every owned point of the mesh into one accumulator, which can hold as many results as the caller likes: the norms of several variables, of several regions, of several weightings, in one sweep and one collective.

  • rf(acc, p) -> acc folds one point into the accumulator. p is a TreeAMR.FoldPoint: the selected variables at the point (p.u), its position (p.x), the block's spacing, level and tag, and its indices.
  • op(a, b) -> acc combines two accumulators — of two lanes, two blocks or two ranks. For an accumulator built from Sum, Max and Min, it is TreeAMR.combine.
  • init is the empty accumulator, and its type is the result's. It must be isbits: a number, a tuple, a NamedTuple or a plain struct of them.
  • vars is an integer or a contiguous range of variable indices, as for block_mapreduce; it selects what p.u holds, not which points are visited.
  • tag = key -> t is an optional host function of a block's MortonKey, whose value reaches rf as p.tag: a block region such as "touches an outer face" is a Bool tag. It must return one isbits type for every block.

The first form reads the working array, skipping the ghosts; the second reads a state vector. Either way the points are exactly the owned points map_blocks! visits, N per dimension, so a vertex-centered block's shared upper plane is not counted and every physical point is counted once.

The laws are those that let a block be split across a device's lanes: op is associative, to roundoff at least; op(init, init) == init; and rf(a, p) == op(a, rf(init, p)). Every sum, maximum, minimum and addto bin update obeys them. A weight is per point: rf multiplies by p.h^D itself where a volume weight is wanted, unlike the per-block weight of mesh_mapreduce, so the same norm through the two differs in its last bits.

Determinism follows the package's rules ("Parallelism" in CODE.md). On the CPU each block is one sequential fold in index order on its owner's thread, so a block's accumulator is bit-identical at every thread count, and the blocks combine in block order. A device folds each block over lanes and then the lanes in order, reproducible from run to run and equal to the CPU's to roundoff. Across ranks the per-rank partials are allgathered and folded in rank order, so maxima, minima and integer counts are bit-identical at any rank count and sums agree to roundoff.

The point count, the sum of squares and the peak of variable 1 inside the shell 1 ≤ |x| < 2, and the sum of squares outside it, in one sweep:

init = (n = Sum(0), sq = (Sum(0.0), Sum(0.0)), peak = Max(0.0))
function rf(acc, p)
    inside = 1 ≤ sqrt(sum(abs2, p.x)) < 2
    q = p.u[1]
    return TreeAMR.combine(acc, (n = Sum(Int(inside)),
                                 sq = addto((Sum(0.0), Sum(0.0)), inside ? 1 : 2,
                                            Sum(q * q)),
                                 peak = Max(inside ? abs(q) : 0.0)))
end
r = mesh_fold(rf, TreeAMR.combine, init, fs; vars=1)
l2 = sqrt(r.sq[1].value / r.n.value)
Callbacks on a device

rf, op and init become kernel arguments, so everything they hold or close over must be isbits: shell radii go in as a tuple, not a Vector, and a captured Type is the usual trip — write oftype(x, 2) rather than closing over T and calling T(2). The accumulator lives in each lane's registers; a large one spills, which costs time but not correctness.

block_fold(rf, op, init, fs::FieldSet; vars=1:fs.nvars, tag=nothing)
block_fold(rf, op, init, fs::FieldSet, u::AbstractVector; vars=1:fs.nvars, tag=nothing)

TreeAMR.FoldPoint — Type
TreeAMR.FoldPoint

What a fold's rf is handed for each owned point (see mesh_fold). It is built inside the kernel and is isbits:

  • p.u: the selected variables at this point, an NTuple in the field set's element type, p.u[1] being variable first(vars);
  • p.x: the point's position, an NTuple{D}, bit for bit what coordinates returns, so a cell center, a vertex or a face center as the field set's centering says;
  • p.h: the block's spacing, so p.h^D is the point's volume weight;
  • p.level: the block's refinement level;
  • p.tag: the block's value of the fold's tag function, or nothing;
  • p.I: the owned index, each entry in 1:N (add G[d] for the stored index, as in map_blocks!);
  • p.b: the local block index.

TreeAMR.Sum — Type
Sum(x)

An accumulator field that TreeAMR.combine combines with +. Sum, Max and Min let a fold's accumulator say how each of its fields combines, so that the caller writes only the per-point rf of mesh_fold and passes TreeAMR.combine as its op:

acc = (n = Sum(0), sq = Sum(0.0), peak = Max(0.0))

The two sides of a Sum must have the same type for the accumulator to keep its type: a Sum(0) and a Sum(1.0) do not combine to a Sum{Int}.

TreeAMR.combine — Function
TreeAMR.combine(a, b)

Combine two accumulators built from Sum, Max and Min, recursing through tuples and NamedTuples: each leaf is combined by its own wrapper. This is the op a fold built from those wrappers passes to mesh_fold and block_fold.

Accumulators of different shapes do not combine: a Sum against a Max, tuples of different lengths or NamedTuples with different names are a MethodError, never a silently wrong number. It is not called merge because Base.merge on two NamedTuples does something else entirely, and quietly.

source
TreeAMR.addto — Function
addto(bins::NTuple{K}, k, x)

bins with x combined into slot k by TreeAMR.combine, and every other slot unchanged. A k outside 1:K changes nothing, so a fold can use 0 for a point that falls in no bin.

This is how a fold bins its points, by shell or by level, say. The tuple is rebuilt with every index a literal rather than indexed at k: a run-time index into a tuple makes a device spill it to local memory, while this keeps the bins in registers for the cost of K selects.
