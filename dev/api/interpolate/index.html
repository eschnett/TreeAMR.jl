Point interpolation

The values of a field set, and their first and second derivatives, at arbitrary points: a horizon finder's surface, a tracer, a sampled ray. One batched launch per call, on the field set's backend; or a batch located once by locate and evaluated at for several field sets.

TreeAMR.interpolate — Function
interpolate(fs, [u,] xs, basis; derivs = (value,), vars = 1:fs.nvars,
            exclude = nothing, atlas = nothing, outside = :error,
            fill = T(NaN)) -> (; values, excluded, inside)

The variables vars of fs, and the derivatives derivs of them, at every point of xs, by tensor-product interpolation in basis — Lagrange(n), or ElementPolynomial() for an element set.

  • xs is an array of points — anything indexable as x[d], an NTuple{D} or an SVector — on the field set's backend, of any shape.
  • values[iv, k, j] is derivative derivs[k] of variable vars[iv] at point xs[j] (linear index), so values[:, k, j] is contiguous. It has the field set's element type and lives on its backend.
  • derivs is a tuple of multi-indices, the derivative order along each dimension: (0, 0, 0) is the value, (1, 0, 0) is ∂ₓ, and the value with the gradient is ((0,0,0), (1,0,0), (0,1,0), (0,0,1)), and (2,0,0) and (1,1,0) are ∂ₓ² and ∂ₓ∂ᵧ. Derivatives are in physical units. Values, first and second derivatives are implemented; a total order of three or more is refused.
  • exclude is an optional Region, and excluded[j] says whether any point of query j's stencil lies inside it. The value is computed either way; what to do with a flagged one is the caller's decision. Without a region every entry is false.
  • outside = :error refuses a point outside the domain; outside = :mark keeps it, with inside[j] == false and every value and derivative of it set to fill. Under :error every inside[j] is true.
  • atlas is the application's map between physical space and the forest's logical coordinates (M19; TreeAMR.chart_locate and its three companions). With one, xs are physical positions, which the atlas maps to a patch and a position there; derivs are physical derivatives, which the chain rule forms from every logical one up to their order through the atlas's Jacobian and Hessian; and exclude is a physical region, tested at the image of every stencil point. Without one, positions and derivatives are the forest's logical ones; on a forest of patches (M17) a point is then a PatchPoint.

The points can be located once and evaluated many times: this call is interpolate(fs, locate(T, fs.forest, xs), basis; …), bit for bit, in one launch rather than two (see locate).

The stencil of a query is the n^D stored points of one block the interpolant reads: the block containing the point (locate_point), and n consecutive stored indices per dimension around it, ghosts included — so the ghosts must be current, filled by fill_ghosts! with the boundary hook, as for any stencil. Near the edge of the stored array the stencil shifts inward rather than extrapolate: centered whenever G ≥ n/2 in a cell-centered dimension and G ≥ n/2 − 1 in a vertex-like one, off center otherwise, and exact on the same polynomials either way — which is what makes a field set with G = 0 interpolable at all. An element-centered set (M16; elementcentered) takes ElementPolynomial() instead, whose stencil is the containing element's own nodes; it reads no ghosts, and so can read a state vector u as well, in the form interpolate(fs, u, xs, basis), which a basis that reads ghosts refuses.

A point is wrapped along a periodic dimension and mirrored once across a reflecting face; a mirrored value takes the variable's parity sign and a derivative across the wall its own sign too, as the ghosts beyond the wall do — once per order across it, so ∂ₓ² across a wall in x keeps the variable's sign and ∂ₓ∂ᵧ flips it. Beyond a rotating seam (M12; see Forest's rotating) the point is turned back into the quadrant by the r quarter turns it lay away, after those folds, and its value is the field set's rotation applied r times there — the variable it names, with its sign — as the ghosts across the seam are; each derivative turns with it, once per order (for r = 1, ∂_{d1} is −∂_{d2} there and ∂_{d2} is ∂_{d1}, so ∂_{d1}∂_{d2} is −∂_{d2}∂_{d1}). A set whose layout is not symmetric in the seam's plane turns into its partner, so it refuses a point beyond the seam, saying so. A point outside the domain after all that is an ArgumentError, raised once the whole batch has run. exclude is tested against the stencil's points where they are, in the block that is read, after every fold.

Every query writes only its own slots, so the result does not depend on the thread count. The batch is one kernel launch; see "Point interpolation" in CODE.md.

Over a distributed forest (M7) the call is collective: every rank calls it with the same field set, basis, derivs, vars and exclude, and with its own points — any number, none included — and gets the answers for its own points, in its own order. Each point is located on the calling rank, sent to the rank that stores its block, evaluated there by the same kernel as serially and sent back, so every value and flag is bit for bit the serial one, whatever the number of ranks. A point outside the domain on any rank is refused on every rank together, before anything is sent: the rank that passed it names it, and the others name the first rank that did. So is an argument that some ranks' checks refuse, or derivs, vars, exclude or the basis differing between ranks. A device backend's points and results go through the host for the messages (see "Distributed meshes" in CODE.md).

interpolate(fs, pts::LocatedPoints, basis; derivs, vars, exclude,
            fill = T(NaN)) -> (; values, excluded, inside)

interpolate at points locate found, without searching again: the same values and flags, bit for bit, as the form that takes the points themselves. inside is pts.inside, and a point outside the domain — kept by locate(…; outside = :mark) — has every value and derivative set to fill, which a heatmap draws transparent as NaN, and excluded false.

TreeAMR.locate — Function
locate([T,] forest, xs; atlas = nothing, outside = :error,
       backend) -> LocatedPoints

The points xs located in forest, once, for any number of interpolate calls over field sets on it. Each point is folded into the domain as interpolate folds it — wrapped along a periodic dimension, mirrored once across a reflecting face, turned back across a rotating seam — and the leaf containing it found by one binary search (locate_point).

T is the type the points are converted to before they are folded and which their positions are kept in; it defaults to the forest's geometry type. interpolate takes a batch located in the field set's own element type only, since the conversion decides which leaf a point on a face goes to: interpolate(fs, xs, basis) is interpolate(fs, locate(T, fs.forest, xs), basis) for a set of type T, bit for bit.

On a forest of patches a point is a PatchPoint, and with an atlas on either a physical position: the application's atlas maps it to a patch and a logical position there through chart_locate, which runs for every point in the launch, and interpolate then returns physical derivatives through the chain rule. The atlas folds the global topology and returns a position inside its patch's closed box; one outside it, but past a reflecting face, which TreeAMR mirrors, is refused as a broken contract, naming the atlas.

outside says what a point outside the domain, or in no patch, does: :error refuses the batch, naming the first such point; :mark keeps it, with pts.inside[j] == false, and interpolate fills its values with its fill.

The points live on the backend of xs, and so does the result; a grid (UniformGrid, AffineGrid, PatchGrid), which is computed from the index, is located on backend, the CPU unless given. The location is one launch there; a regrid makes it stale.

TreeAMR.LocatedPoints — Type
LocatedPoints

A batch of points located in a forest by locate, for interpolate to evaluate field sets at without searching again: a horizon finder reads the metric with its gradient and the extrinsic curvature without it from one location, and a viewer locates its grid once per regrid rather than once per frame.

It holds, per point and on the points' backend, the global leaf the point lies in (0 for a point outside the domain), its patch, the position as given and as folded into the domain, the fold, and whether the point is inside; and with them the forest and its generation, so that a batch a regrid has made stale is refused rather than read from the wrong blocks. length(pts) is the number of points, and pts.inside the flags.

source
TreeAMR.PatchPoint — Type
PatchPoint(ξ, p)

A point given as a logical position ξ in patch p of a forest of patches (M17), which is how locate, interpolate and locate_point take a point there, where a plain position names a point in every patch whose box holds it. ξ is located in patch p alone: TreeAMR follows no glue, so a ξ outside the patch's box is outside (but for the mirror at a reflecting face, which carries the variable's parity), and a ξ on a glued face belongs to patch p, to its last leaf there. On a brick, patch 1 is the brick.

source
TreeAMR.locate_point — Function
locate_point(forest, x) -> Union{Int,Nothing}

The index into forest.leaves of the leaf containing the point x, or nothing when x is outside the domain. It is a global leaf index, as every tree query's is: serially it is also the block index of every FieldSet over forest, and over a distributed forest the block is stored by the rank whose blockrange contains it.

Leaves own half-open boxes, so a point on a face shared by two leaves belongs to the upper one; a point on the domain's upper face belongs to the last leaf there. Along a periodic dimension x is wrapped into the domain first, beyond a reflecting face it is mirrored once, and beyond a rotating seam (M12) it is turned back into the quadrant by as many quarter turns as it lay away — which is where interpolate reads its value. O(D·maxlevel + log nleaves): one binary search over the sorted leaves.

On a forest of patches (M17) a point is a PatchPoint(ξ, p), located in patch p alone; a plain position is refused there.

TreeAMR.InterpolationBasis — Type
InterpolationBasis

The one-dimensional interpolant interpolate builds its tensor product from. Lagrange is the only one implemented.

A basis is the extension point for interpolants with other properties — a smooth (C¹) one built from the same nodal data, say, where Lagrange interpolation is only continuous. A new basis is a subtype that is isbits (it becomes a kernel argument) and implements three internal functions, which are everything the kernel asks of it:

  • TreeAMR.stencilwidth(basis): the number n of consecutive stored points per dimension it reads, a compile-time constant of the type;
  • TreeAMR.stencilstart(basis, t, G, c, S): the first of them and the query's offset ξ from it, as (first, ξ), given the query's position t in spacings from the block's origin, and along that dimension the set's ghost width G, its stagger c (1 for vertex-like, 0 otherwise) and the stored size S; first must lie in 1 : S − n + 1, so that the stencil is inside the block's stored array;
  • TreeAMR.basisweights(basis, ξ, Val(M)): the n weights and their first M derivatives at ξ, in spacings, as an (M+1)-tuple of n-tuples;

and TreeAMR.check_derivative(basis, m) if it cannot produce every derivative order below n, and TreeAMR.stencil_place(basis, origin, h, first, Val(G), Val(C)) if its stencil points are not the stored points of an equally spaced set — the positions an exclude region is tested at. The position, rather than a stored index, is what the kernel hands a basis because an element set's stored index is not linear in it.

TreeAMR.Lagrange — Type
Lagrange(n)

Tensor-product Lagrange interpolation through n consecutive stored points per dimension: exact on polynomials of degree n − 1 in each dimension, error O(hⁿ) for the value and O(hⁿ⁻ᵐ) for an m-th derivative along one dimension; a mixed derivative converges at the rate of its highest single order, ∂ₓ∂ᵧ as O(hⁿ⁻¹). Near a coarse-fine face the stencil reads ghosts, which carry the exchange's O(hᵖ) error, and a derivative of total order |m| divides that by h^|m|; so the rate is min(n − maxₐ mₐ, p − |m|), and the full mixed rate needs p ≥ n + 1.

n has no default: the right order follows from what the field is used for, as for Operators. Interpolating an evolved state one order above the scheme's accuracy keeps the interpolation error below the solution's.

The stencil is centered on the query for even n and half a point off for odd n, and in both cases it changes only at a stored point, where every choice of stencil interpolates the same value. So the interpolant is continuous inside a block — C⁰, not C¹: its first and second derivatives jump at the stored points. Near the edge of the stored array the stencil shifts inward rather than extrapolate (see interpolate).

TreeAMR.ElementPolynomial — Type
ElementPolynomial()

The interpolant of an element-centered set (M16; elementcentered): the degree-P tensor polynomial of the element containing the point, through its (P+1)ᴰ Gauss–Lobatto nodes, with P the field set's. It is exact on Q_P, the value converges as O(h^{P+1}) and a derivative as O(h^{P+1−maxₐ mₐ}); a derivative of order above P along a dimension is identically zero and refused.

It reads the element's own nodes and no ghosts, so it needs no fill_ghosts!, reads a state vector as well as the working array (interpolate(fs, u, xs, basis)), and picks up none of the exchange's error at a coarse-fine face. It is discontinuous across element faces: the value jumps there by the solution's own O(h^{P+1}), a first derivative by O(h^P). A point on an element face takes the upper element, as a point on a block face takes the upper block.

A set without elements takes Lagrange instead, and an element set takes this basis only. See "Interpolation on element sets and patches" in CODE.md.

TreeAMR.Region — Type
Region

A region of the domain whose data an interpolation must not silently use: interpolate's exclude flags every query whose stencil has a point inside it. Ellipsoid is the one implemented.

A new region is an isbits subtype implementing TreeAMR.inside(region, x) for a point x::NTuple{D,T}, and TreeAMR.convertregion(T, region) if its parameters must be brought to the field set's type. It may also override TreeAMR.stencil_hits(region, origin, h, base, off, Val(n)) with something cheaper than the default, which tests all n^D stencil points of an equally spaced set, point k (from 0) along dimension d at TreeAMR.stencil_position(origin, h, base, off, d, k). An element set's stencil (M19), whose nodes are not equally spaced, is tested by TreeAMR.stencil_hits(region, place, Val(n)) at TreeAMR.stencil_position(place, d, k), whose default tests every point.

source
TreeAMR.Ellipsoid — Type
Ellipsoid(center, semiaxes)

The open axis-aligned ellipsoid Σ_d ((x_d − c_d)/a_d)² < 1; a ball is Ellipsoid(c, (r, r, r)). Used as interpolate's exclude region, for data that is not a solution inside it — the interior of a black hole kept only as a damping layer, say.

Testing a stencil against it costs O(D·n), not O(n^D), and is exact rather than conservative: the sum is separable, so the stencil point nearest the center in the scaled metric is the per-dimension nearest, and the stencil reaches inside iff that one point does.

source
TreeAMR.multi_indices — Function
multi_indices(Val(D), maxorder) -> NTuple

Every derivative multi-index in D dimensions up to total order maxorder ≤ 2, in a fixed order: the value, then the first derivatives by dimension, then the second derivatives ∂_a∂_b with a ≤ b in lexicographic order. derivs = multi_indices(Val(3), 1) asks interpolate for the value with the gradient.

Point sets

Grids computed from the index, which reach a kernel as one value, and the lattice of sub-centres of every element.

TreeAMR.AbstractPointGrid — Type
AbstractPointGrid{D,T,K} <: AbstractArray{NTuple{D,T},K}

A K-dimensional array of points in D dimensions computed from the index, which locate and interpolate take as they take an array of points, on any backend: UniformGrid, AffineGrid, and PatchGrid of either.

source
TreeAMR.UniformGrid — Type
UniformGrid(lo, hi, dims)

The prod(dims) points of a regular grid filling the box from lo to hi, both corners included, dims[d] points along dimension d (a single point lies at lo): lo[d] + (i_d − 1)·(hi[d] − lo[d])/(dims[d] − 1), with the step formed once. An isbits array, so it reaches a kernel as one argument; collect gives the same points.

source
TreeAMR.AffineGrid — Type
AffineGrid(origin, axes, dims)

The points origin + Σₖ (iₖ − 1)·axes[k] for 1 ≤ iₖ ≤ dims[k], with K = length(axes) ≤ D axes, each a D-vector: a line, a plane or a box at any orientation, through a D-dimensional domain. An isbits array, so it reaches a kernel as one argument; collect gives the same points.

source
TreeAMR.PatchGrid — Type
PatchGrid(grid, p)

The points of grid — a UniformGrid or an AffineGrid of logical positions — as PatchPoints of patch p of a forest of patches, in the grid's shape and order.

source
TreeAMR.element_lattice — Function
element_lattice(fs, k; atlas = nothing) -> LocatedPoints

The centres of a k-fold subdivision of every element of every local block of fs — of every cell, for a set without elements — as located points, without a search: kᴰ per element, block by block and, within a block, in the lexicographic order of the sub-cells along each dimension. No point is on a face, so each is in the element it was made in. positions gives them, physical through the atlas's chart_map when there is one, which also makes interpolate's derivatives at them physical.

The points are those of this rank's blocks, so over a distributed forest every rank evaluates its own, with no messages.

source
TreeAMR.positions — Function
positions(pts::LocatedPoints) -> AbstractVector

The position of every located point, on the points' backend: logical without an atlas — on a forest of patches the position in its patch, pts.patch saying which — and physical through chart_map with one. A point outside keeps the position it was given.

The atlas

An application's maps between physical space and its patches' logical coordinates, recognised by these methods alone.

TreeAMR.chart_locate — Function
TreeAMR.chart_locate(atlas, x) -> (ξ, p) or nothing

The logical position ξ::NTuple{D} in patch p::Int of the physical point x::NTuple{D,T}, or nothing when x lies in no patch — in an annulus's hole, beyond a ball's surface. The application defines it for its atlas; locate calls it for every point.

It folds the domain's global topology itself, wrapping an angle or choosing which of a ball's patches a point is in, and returns a ξ in patch p's closed box: a ξ outside it, but for one past a reflecting face, is refused as a broken contract, naming the atlas. On a brick, p is 1 and the brick's own folds apply to ξ as to a position. Inverting the map is the atlas's: TreeAMR offers no Newton iteration.

source
TreeAMR.chart_map — Function
TreeAMR.chart_map(atlas, ξ, p) -> x

The physical position of logical position ξ in patch p: the inverse of chart_locate. Needed for an exclude region with an atlas, which is physical, and for positions.

source
TreeAMR.chart_jacobian — Function
TreeAMR.chart_jacobian(atlas, ξ, p) -> J

The Jacobian of chart_map at ξ in patch p, as an NTuple{D} of NTuple{D}s with J[i][a] = ∂xⁱ/∂ξᵃ. Needed for a first or second derivative with an atlas, which interpolate returns in physical units through the chain rule.

source
TreeAMR.chart_hessian — Function
TreeAMR.chart_hessian(atlas, ξ, p) -> H

The second derivatives of chart_map at ξ in patch p, H[i][a][b] = ∂²xⁱ/∂ξᵃ∂ξᵇ. Needed only for a second derivative with an atlas.
